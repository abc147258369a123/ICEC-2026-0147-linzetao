## 1. 这块固件解决什么问题

一台旧充电宝「感觉不撑用了」，但用户拿不到任何数字。
拆开之后能测到电压电流，却仍然答不出三个问题：

1. 它现在真实可用容量是多少？掉到标称的百分之几？
2. 电芯内阻涨到多少了？离「该换了」还有多远？
3. 这次放电是从满到截止的完整一程，还是中途拔掉了？

这块固件把这三个问题变成持续输出的 CSV：

```
t_ms,V_bus,I,P,Ah_out,Ah_in,Wh_out,Wh_in,R_mohm,SOH_R,SOH_C,flag
```

- **Ah_out / Wh_out** —— 库仑计与瓦时计，逐次累加（0.1 Ah 分辨率）
- **R_mohm** —— 内阻，用**负载阶跃法** `R = |ΔV| / |ΔI|` 实时估算，中值滤波
- **SOH_R** —— 内阻法健康度 = 参考内阻 ÷ 实测内阻
- **SOH_C** —— 容量法健康度 = 实测放电容量 ÷ 标称容量
- **flag** —— 接近 INA219 量程时打 `CLIP?`，防止削顶数据被当成真的

## 2. 接线

| INA219 引脚 | 接到 | 说明 |
| --- | --- | --- |
| VCC | 3.3 V | 模块自带稳压时也可接 5 V，看模块丝印 |
| GND | GND | **必须共地**，否则读数全乱 |
| SDA | ESP32-C3 **GPIO8** | 可在 `main.cpp` 顶部改 |
| SCL | ESP32-C3 **GPIO9** | 同上 |
| VIN+ / VIN− | **串在被测支路里** | 见下方接线方向说明 |

### 接在哪个位置（关键）

```
电芯 BAT+ ──> R_SHUNT(0.05Ω) ──> 原板 BAT+ 焊盘
                 │
            INA219 VIN+ / VIN−
```

即**把 0.05 Ω 采样电阻串在电芯正极与主板 BAT+ 之间**。
这样测到的是电芯侧真实电流，充放电都能测，且不受升压级效率影响。

**方向约定：** 本固件把 `I > 0` 解释为**放电**（电流流出电芯）。
如果接完发现放电时读数是负的，把 VIN+/VIN− 两根线对调即可——
不用改代码，代码里的符号约定是稳定的。

### ⚠️ 三个必须注意的地方

1. **采样电阻要 0.05 Ω，不是常见的 0.1 Ω。**
   INA219 的 PGA 上限是 ±320 mV，0.1 Ω 时量程只有 3.2 A。
   30 W 快充时电芯侧电流可达 4 A，会**削顶**，读数直接失真。
   0.05 Ω 时量程 6.4 A、分辨率 0.2 mA，够用。
2. **必须共地。** INA219 的 GND 与充电宝的 GND 不是同一个网络时，
   I2C 通信会时好时坏，表现为偶发 `WARN: I2C 读失败`。
3. **取电从哪儿来。** ESP32-C3 直接吃充电宝的 5 V 输出，
   经板载 LDO 降到 3.3 V；**不要从电芯 BAT+ 直接喂 3.3 V 模块**（4.2 V 会超压）。

## 5. 四个必须自己动手标定的参数

位于 `src/main.cpp` 顶部，**注释里都写了 TODO**：

| 参数 | 当前值 | 怎么标定 |
| --- | --- | --- |
| `R_SHUNT` | 0.05 Ω | 换成你实际焊的那颗的阻值；万用表四线法量一下更准 |
| `R_NOMINAL_MOHM` | **140.0 mΩ** | 拆机后对健康 2S 电芯组做阶跃测试，读出的 `R_mohm` 就是参考值 |
| `CAP_NOMINAL_AH` | **4.90 Ah** | 已按铭牌核实：2S 7.3 V / 4900 mAh（串联时容量不叠加） |
| `I_DEADBAND` | 0.005 A | 静置时看串口噪声，取略高于噪声的值 |

### 2S 结构带来的三处影响（已按铭牌更新代码）

铭牌实测：**电池组 7.3 V / 4900 mAh，2S 串联**。这一点改变了三处默认值：

| 项 | 1S 假设下（错误） | 2S 实际（已修正） |
| --- | --- | --- |
| `CAP_NOMINAL_AH` | 10.0 Ah | **4.90 Ah**（串联容量不叠加） |
| `R_NOMINAL_MOHM` | 60 mΩ | **140 mΩ**（整组约为单节 2 倍） |
| 9 V 输出升压比 | 2.43× | **1.23×** |

> **SOH_R 在没有标定 `R_NOMINAL_MOHM` 之前是没有意义的数字。**
> 别把 140 mΩ 这个占位值当成结论写进报告。

## 6. 已知局限（写进报告里，别藏着）

1. **内阻法在恒流条件下失效。** 阶跃法需要负载电流**发生变化**才能算 R。
   如果被测对象一直是恒定电流放电，`R_mohm` 会一直是 `nan`。
   破解办法：中途人为改变一次负载（插拔手机），制造阶跃。
2. **容量法需要完整一程放电。** 中途拔线不会更新 `SOH_C`（`g_ahDip` 会被放弃）。
3. **没有掉电保存。** 断电后累计值归零。要跨天连续记录，
   靠上位机脚本落盘，不靠固件。
4. **未做温度补偿。** 内阻随温度变化明显，冬季读数会偏高。
   报告里需记录测试时环境温度。

## 7. 这一项怎么拿满 20 分

大纲原话是「动手完成接线验证直接满分」。所以评分锚点是**通电跑起来**，
不是方案写得多漂亮。最低限度的证据链：

- [ ] 接线照片（能看清 INA219 串在哪个焊点上）
- [ ] 串口终端截图（能看到 CSV 行在滚）
- [ ] `process_logs/` 里有连续多天的串口记录文件
- [ ] 一段 30 s 视频：插上负载 → 电流变化 → `R_mohm` 出数 → 拔掉 → 归零
- [ ] 改造后**原功能未被破坏**（充电宝还能正常充放电）

最后一条最容易被忽略：**改造不能把原来的东西弄坏。**
坏了就说明你的取电点和隔离没做好，这一项会从满分掉下来。
