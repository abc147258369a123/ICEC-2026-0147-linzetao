# process_logs · 跨多日连续过程数据

> ⚠️ **这是第二阶段的准入条件，不是加分项。**
> 考核大纲原文：「**强制要求提交跨多日连续过程数据（process_logs/）**」
> 缺失 = 直接不满足该项目的提交资格。

---

## 铁律

1. **每天至少一条记录。** 从 **10/23** 拆解开始，到 **11/24** 封仓，连续 32 天。
2. **时间戳必须是真实的。** 面试第 ① 项会拿它交叉比对：
   - 照片的 EXIF 时间
   - `git log` 的提交时间
   - 你口述的采样子顺序
   三者对不上，等于自证造假。
3. **失败和重试必须记。** 面试第 ④ 项「心理抗压能力与受挫归因模式」专门看这个。
   只记成功 = 过程不真实。
4. **不改写已生成的记录。** 记错了就新增一条纠正记录，不要回头改原文件。

---

## 每天怎么做（30 秒）

### 记一条

```bash
python 工具/field_log.py
```

会依次问：类别 → 事件 → 数值 → 单位 → 状态 → 备注，回车即落盘。

### 收工提交

```bash
git add .
git commit -m "day07: 完成 U1 丝印溯源，确认充电管理 IC 型号"
git push
```

## 类别速查

| 类别 | 用在哪 |
| --- | --- |
| `teardown` | 拆解动作（卸螺丝、开卡扣、分离板件） |
| `measure` | 万用表/电流表读数、阻值、电压 |
| `photo` | 关键照片拍摄（记下文件编号，便于和 EXIF 对） |
| `debug` | 卡住的问题、排查思路、失败尝试 |
| `design` | 改造方案设计决策 |
| `assemble` | 接线、焊接、装配 |
| `poweron` | 通电验证，**这一项最重要（第 ④ 项满分档靠它）** |
| `doc` | 写文档、画框图 |

## 状态速查

| 状态 | 含义 |
| --- | --- |
| `ok` | 正常完成 |
| `fail` | 尝试失败 |
| `suspect` | 读数可疑，待复核 |
| `retry` | 重试 |

时间戳,类别,事件,数值,单位,状态,备注
2026-10-23 14:32:11,teardown,拆下后盖，4 个卡扣,4,pcs,ok,
2026-10-23 15:10:03,measure,VIN 对地阻值,1.2,Mohm,suspect,与预期 8M 差太多
2026-10-23 15:41:20,debug,换表笔复测，阻值恢复正常,8.6,Mohm,ok,前一次是表笔接触不良
2026-10-24 09:15:32,measure,U1 丝印字符,待填,,-,ok,放大镜+手机微距拍摄，随后查 datasheet 核对
2026-10-25 16:02:44,poweron,改造板首次上电，串口输出正常,-,-,ok,INA219 读到 3.87V

> 倒数第二行和最后一行放在一起，才是**真实**的过程记录。
> 只留成功那行，评委会怀疑你没真做。
