## 二、命名规范

```
YYYYMMDD_类型_序号.jpg
```

**示例：**

```
20261015_nameplate_01.jpg      铭牌特写
20261015_onsite_01.jpg         本人同框
20261015_setup_01.jpg          接线拓扑
20261015_screen_01.jpg         功率计读数
```

**为什么这样命名：**

1. **日期在最前面** —— 文件管理器按名字排序就是按时间排序，和 `git log` 时间线天然对齐
2. **类型在中间** —— 评委一眼知道这张是什么，不用点开
3. **序号在最后** —— 同类型多张不会互相覆盖

## 三、传输防坑（最重要的一节）

手机照片里存着拍摄时间、设备型号等 **EXIF** 信息。
**它是证明「照片是那天拍的」唯一手段。** 一旦被抹掉，照片就只是一张图。

| 操作 | 结果 | 结论 |
| --- | --- | --- |
| 微信/QQ 发给「文件传输助手」再保存 | 压缩 + **抹掉 EXIF** | ❌ 绝对不行 |
| 微信聊天里「保存图片」 | 压缩 + 抹掉 EXIF | ❌ 绝对不行 |
| 手机截图 | 无原始 EXIF，只有截图时间 | ❌ 不行 |
| 任何「图片压缩」App | 抹掉 EXIF | ❌ 不行 |
| **数据线直连，从 `DCIM/` 复制原文件** | 原样保留 | ✅ 推荐 |
| 云盘下载「原始大小」版本 | 原样保留（需确认设置） | ✅ 可以 |

### 怎么确认 EXIF 还在

Windows 上：右键图片 → **属性** → **详细信息** 标签页
→ 看有没有「拍摄日期」「相机型号」两行。

如果「拍摄日期」是空的，这张照片**不能用作过程证据**。

### iPhone 用户额外注意

- 默认格式是 **HEIC**，GitHub 页面不预览（显示成破图）
- 提交前先转 JPG：手机「设置 → 相机 → 格式 → 兼容性最佳」，
  或者用电脑上「画图」/「照片」另存为 JPG
- **转换后要重新检查 EXIF 是否还在**（部分转换工具会丢掉）

## 四、提交命令

照片放进本目录后：

```powershell
cd "E:\Users\LIN\Documents\deepseek-harness\default-workspace\ICEC-2026-0147-linzetao"

git status                       # 确认照片在里面
git add 01-Field-Discovery/T07-PowerBank-Efficiency/raw_data/
git commit -m "data(T07): 补充铭牌照片与现场同框照片"
git push
```

**或者用 GitHub 网页上传：**
打开仓库对应目录页面 → `Add file` → `Upload files` → 拖入照片 → `Commit changes`。

> 网页上传对少量照片更方便，但**一次传太多（>20 张）容易失败**，
> 批量请用 git 命令行。

## 五、体积限制

| 限制项 | 数值 | 说明 |
| --- | --- | --- |
| 单文件上限 | **100 MB** | 手机照片 3–6 MB，远远够用 |
| 仓库建议上限 | 1 GB | 40 天全部照片也就几百 MB |
| 本仓库当前大小 | 约 5 MB | 主要是 4 张图 + 原始 CSV |

> **视频不要进仓库。** 拆解视频、路演视频动辄几百 MB，
> 放网盘（百度网盘/阿里云盘），仓库里只放**关键帧截图**，并在报告里给网盘链接。
